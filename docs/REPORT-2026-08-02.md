## 1. 앱 마크를 서가로

제목 옆이 비어 있어 마크를 붙이는 것으로 시작했다. 처음 넣은 것은 펼친 책
한 권이었는데, 후보 여섯 개(독서대·서가·읽는 사람·갈피·책방·쌓인 책)를 실제
크기로 그려 비교한 뒤 **서가**로 정했다.

- `src/components/brand-mark.tsx` — 꽂힌 책 세 권 + 기대어 선 한 권 + 선반
- `src/app/icons/[size]/route.tsx` — PWA 아이콘도 같은 형상으로

**결정 근거와 함정**

- 마크를 `<h1>` 안에 **인라인**으로 둔다. h1을 flex로 만들면 바깥 컨테이너의
  `items-baseline`이 글자가 아니라 svg 아래끝을 기준으로 잡아 오른쪽
  UserBadge와 어긋난다.
- 아이콘 라우트는 satori라 SVG path를 못 그린다. 박스로 쌓고, 회전축이 박스
  중심이라 기울인 만큼 여백으로 되돌린다.
- 아이콘 쪽 색은 값을 박아야 하고(ImageResponse가 CSS 변수를 모른다) 마크는
  토큰을 따라간다. 두 곳의 색이 갈라지는 것은 의도한 것이다.

## 2. 세피아 테마

라이트(밝기 0.977)와 다크(0.228) 사이가 없었다. 밝기 **0.905**에 노랑 채도를
올린 미색 종이톤을 넣고, 시스템 설정은 기존대로 라이트/다크만 따라가게 뒀다.

- 선택지: 시스템(기본) · 라이트 · 다크 · **세피아** — 순서가 곧 버튼 순서다
- 글자 대비 약 9:1. 라이트(약 13:1)보다 낮지만 본문 기준(4.5:1)에는 여유가
  있다. **대비를 낮추는 것이 이 테마의 목적이다.**

**걸러낸 것 — Tailwind 이름 충돌**

html 클래스를 `sepia`로 두면 **화면 전체에 `filter: sepia(100%)`가 걸린다.**
Tailwind에 같은 이름의 필터 유틸리티가 있고, 빌드된 CSS에 실제로 그 규칙이
들어 있는 것을 확인했다. 클래스만 `theme-sepia`로 피했다(저장값은 `sepia`).
단위·E2E 양쪽에 이 단정을 남겼다.

**그 밖에**

- 세피아는 OS에 짝이 없다. `resolveTheme`이 시스템일 때 내놓지 않는다.
- `prefers-color-scheme: dark` 규칙의 선택자에서 `:not(.theme-sepia)`로 빼야
  OS가 다크일 때 세피아가 덮이지 않는다.

## 3. 버튼과 컨트롤을 앱 감각으로

화면을 하나씩 고치는 대신 24개 파일이 공유하는 `ui/styles.ts`를 다시 썼다.

1. **누를 자리는 44px**(`min-h-11`). 글자 크기가 아니라 높이로 잡는다.
2. **누르면 반응한다**(`active:scale-[0.97]`). hover는 마우스에만 있다.
   탭 하이라이트를 끄고 `touch-action: manipulation`으로 iOS 300ms 지연 제거.
3. **테두리보다 면.** 입력칸을 `bg-secondary`로 채우고 테두리는 포커스에서만.
4. **밑줄 링크 폐지.** 보조 동작 32곳이 눌리는 알약이 됐다.

- 네이티브 `<select>` 15곳 → `ui/select.tsx`. 목록은 OS가 그리게 두고 화살표만
  바꾼다. 배경 이미지가 아니라 svg인 이유는 색이다 — data URI에는 색을 박아야
  해서 테마 셋 중 한 곳에서 반드시 어긋난다.
- 밑줄 탭 → 세그먼티드 컨트롤(테마 · 서재 상태 · 리스트/그리드).
- 포커스 링을 ring → outline. outline은 border-radius를 따라가므로 알약
  버튼에 각진 테두리가 씌워지지 않는다.
- 상단 이동 링크에 아이콘(집 · 조절 손잡이 · 펼친 책 · 꺾쇠). 패키지를 들이지
  않고 직접 그렸다 — 우리가 그린 마크 옆에 다른 그림체가 서지 않도록.

**작업 중 실제로 잡은 것 둘**

- **iOS 확대.** 본문 눈금이 15px이라 Safari가 입력칸 포커스마다 화면을
  확대했다. 좁은 화면에서만 입력 요소를 16px로 올려 막았다.
- **다크에서 고른 칸이 가라앉음.** 세그먼티드 컨트롤에 `bg-card`를 쓰면
  다크에서 card가 트랙(secondary)보다 어둡다. `--elevated` 토큰을 새로 뒀다.

첫 아이콘 두 개는 16px로 뽑아 확대해보고 버렸다. 톱니바퀴는 이·굴대·테가
붙어 동그란 덩어리로 뭉갰고, 서가 아이콘은 `00\`처럼 보인 데다 제목 옆 마크와
같은 그림이었다.

## 4. 프로덕션 로그인 장애 (원인 규명)

**증상**: 배포 도메인에서 `kyhoon75@gmail.com`으로 로그인 링크를 요청하면
오류가 나고 메일이 오지 않는다.

**조사** (전부 읽기 전용 조회, 메일을 새로 보내지 않았다)

| 확인 항목                          | 결과                                         |
| ---------------------------------- | -------------------------------------------- |
| 프로덕션 번들의 Supabase 접속 정보 | 정상 — 올바른 프로젝트 + 46자 publishable 키 |
| 이메일 로그인 · 신규 가입          | `email: true`, `disable_signup: false`       |
| Redirect URL 허용 목록             | 배포 도메인의 `/auth/confirm` **허용됨**     |
| 계정 상태                          | 존재 · 확인됨 · 08-01 09:26 정상 로그인      |
| 당일 발송 기록                     | **`recovery_sent_at: 08-02 09:40:28 KST`**   |

마지막 줄이 결론을 갈랐다. GoTrue는 메일 서버가 링크를 받아준 뒤에야 이
시각을 기록한다. 즉 **요청 하나는 API와 발송을 모두 통과했다.** 설정 문제가
아니었다.

**원인**: Supabase 기본 메일 서비스의 발송 한도(같은 주소 60초 간격, 프로젝트
시간당 2통). 한 통 나간 직후 다시 누르면 429가 나고, 앱이 그것을 "잠시 후
다시 시도해주세요" 한 줄로 덮고 있었다.

**진단을 막고 있던 것은 앱 자신이었다.** `login-form.tsx`가 Supabase 오류를
통째로 버려서, 발송 한도인지 설정 문제인지 주소 문제인지 화면으로 구분할 수
없었다. `lib/auth/login-error.ts`를 만들어 code별로 다른 안내를 내보내고
콘솔에 원문을 남기게 했다. 5xx일 때 "주소 문제가 아니다"라고 못박는 것도
넣었다 — 안 그러면 멀쩡한 주소를 고치며 헤맨다.

## 5. Google 로그인

메일 도착 시점과 발송 한도에 매인 단계 자체를 없앴다.

- 로그인 화면 맨 위에 "Google 계정으로 계속하기". 매직링크는 아래 남겼다.
- **콜백은 그대로다.** `/auth/confirm`이 이미 PKCE의 `?code=`를 세션으로
  교환하고 있어서 라우트를 손대지 않았다.
- `redirect_to`를 만드는 곳을 `lib/auth/redirect-to.ts` 한 군데로 모았다.

**함정**: 이 주소가 Supabase 허용 목록에 없으면 **오류 없이** Site URL로
갈아끼워진다. 로그인은 되는데 엉뚱한 도메인에 세션이 생겨 알아채기 어렵다.
E2E가 `redirect_to`를 단정한다.

**설정 검증** (사용자가 대시보드 설정을 마친 뒤 조회)

| 확인                   | 결과                                                   |
| ---------------------- | ------------------------------------------------------ |
| Supabase Google 공급자 | `google: true`                                         |
| Supabase → 구글 인계   | `accounts.google.com`으로 이동, `scope: email profile` |
| OAuth 클라이언트       | `invalid_client` 없음                                  |
| 리디렉션 주소 등록     | `redirect_uri_mismatch` 없음                           |

실제 로그인 성공은 사용자가 확인했다.

## 6. 남은 것

**사용자 설정 (대시보드, 저장소 밖)**

1. **OAuth 동의 화면 게시 시 신규 가입을 닫을 것.** 지금까지 구글의 테스트
   사용자 목록이 사실상 출입 명단이었다. 게시하면 그게 없어져 **구글 계정이
   있는 누구나 이 앱에 계정을 만들 수 있다.** RLS가 남의 기록은 막지만 가입
   자체는 막지 않는다. Supabase Authentication → "Allow new users to sign up"을
   끄면 기존 계정은 그대로 들어오고 처음 오는 사람만 거부된다.
   거부 문구는 이미 준비돼 있다(`signup_disabled` 매핑).
   - 참고: 이 앱의 범위는 `email profile` 뿐이라 구글 검수 대상이 아니다.
     게시해도 "확인되지 않은 앱" 경고가 뜨지 않는다.
2. 매직링크를 계속 쓰려면 **커스텀 SMTP** 연결이 필요하다. 기본 서비스의
   시간당 2통은 대시보드에서 올릴 수 없다.

**코드 백로그**

- 하단 탭 바(홈 · 서재 · 등록 · 설정 고정). 컨트롤이 아니라 네비게이션
  구조라 이번에 손대지 않았다.
- 쓰이지 않는 `src/components/ui/button.tsx`(shadcn 스캐폴딩) 정리.
- 테마 색을 주소창까지 반영하기. `viewport.themeColor`는
  `prefers-color-scheme` 기반이라 세피아를 표현할 수 없다. 라이트/다크를
  OS와 반대로 고정했을 때도 원래 같은 현상이라 이번 변경으로 생긴 문제는
  아니다.
