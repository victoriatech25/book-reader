## 5. 주의점

### 5.1 자격증명

- **`.env.local`은 커밋 대상이 아니다.** 저장소가 **public**이라 키가 한 번 올라가면 되돌릴 수 없다.
- Supabase 키는 **신규 체계**를 쓴다. Settings → **API Keys**의 `Publishable`(`sb_publishable_…`)과 `Secret`(`sb_secret_…`). Settings → **JWT Keys**에 있는 구형 `anon`/`service_role` JWT는 **쓰지 않는다.** 두 체계를 섞으면 구형 키 폐기 시 깨진다.
- **`NEXT_PUBLIC_SUPABASE_URL`에 `/rest/v1`을 붙이지 않는다.** `supabase-js`가 스스로 붙여서 `/rest/v1/rest/v1/…`이 되고 전부 404가 난다. 끝 슬래시도 없이 `https://<ref>.supabase.co`.
- **`SUPABASE_SERVICE_ROLE_KEY`는 RLS를 우회한다.** 사용처는 세 곳뿐 — 마이그레이션·시드, `verify-rls.mjs`, E2E 세션 주입. **클라이언트 코드에서 절대 참조하지 않는다.**

### 5.2 데이터베이스

- **마이그레이션은 항상 `supabase/migrations/` 파일로만.** 콘솔 SQL 에디터에서 직접 고치면 다음 세션이 스키마 상태를 알 수 없다.
- **원격에 이미 적용됐고 실사용 데이터가 들어가기 시작한다.** G3부터는 **DB 리셋 금지**. 스키마 변경은 새 up 마이그레이션 + 데이터 이행으로만 한다.
- `supabase link`는 완료 상태다. 적용은 `pnpm db:push`, 타입 재생성은 `pnpm db:types`.
- **`src/types/database.ts`는 생성물이다.** 손으로 고치지 말고 스키마를 바꾼 뒤 `pnpm db:types`로 다시 뽑는다.

### 5.2b 로그인 (2026-08-02에 실제로 막혔던 것)

- **Supabase 기본 메일 서비스로는 프로덕션을 못 굴린다.** 시간당 2통이 고정 한도이고 대시보드에서 올릴 수 없다. 한도를 조정하려면 커스텀 SMTP를 먼저 붙여야 한다. 연달아 누르면 429가 나고, 그게 "로그인이 안 된다"의 정체였다.
- **그래서 Google 로그인이 기본이다.** 발송이라는 단계가 없으니 한도도 도착 지연도 없다. 매직링크는 대체 수단으로 남겼다.
- **두 방식이 콜백을 공유한다.** `/auth/confirm`이 `?code=`(PKCE·OAuth)와 `?token_hash=`(메일 템플릿)를 모두 받는다. 주소는 `lib/auth/redirect-to.ts`가 한 곳에서 만든다.
- **Redirect URL 허용 목록에 없으면 오류 없이 Site URL로 갈아끼워진다.** 로그인은 되는데 엉뚱한 도메인에 세션이 생겨서 알아채기 어렵다. 배포 도메인이 바뀌면 Supabase Auth 설정부터 확인한다. E2E가 `redirect_to`를 단정한다.
- **로그인 실패 메시지를 뭉개지 않는다.** `lib/auth/login-error.ts`가 GoTrue의 code를 사람 말로 옮기고, 콘솔에 원문을 남긴다. 예전에는 무슨 오류든 "잠시 후 다시 시도해주세요" 한 줄이라 화면만 보고는 원인을 좁힐 수 없었다.

### 5.3 도메인 규칙 (어기면 데이터가 조용히 이상해진다)

- **`user_id`는 서버가 세션에서 넣는다.** 클라이언트가 보낸 값을 믿지 않는다. RLS의 `with check`가 위조를 거부하는 것을 V3가 검증한다.
- **소급 등록한 책의 시작일은 완독 시점과 같다.** DB 제약(`readings_started_ts`)이 완독 회차에 시작일을 요구하는데 옛날 책의 시작일은 알 수 없다. 그래서 "완독 소요일"이 0으로 나오는 것은 버그가 아니다. 진행 기록도 없어 **독서 시간 통계에 잡히지 않는다** — 화면에서 그렇다고 알린다.
- **완독 시기는 년-월까지만 받고 그 달 1일 서울 자정으로 저장한다.** UTC 자정으로 넣으면 서울 기준 앞 달 마지막 날이 되어 통계가 한 달씩 밀린다. `monthToTimestamp()`가 `+09:00`을 명시하는 이유다.
- **재독은 기존 행을 수정하지 않는다.** `attempt_no + 1`로 **새 `readings` 행**을 만든다. 이전 회차의 시작일·완독일·별점·소감이 그대로 남아야 한다 (PRD §2.1 A).
- **진행률 100%는 완독이 아니다.** 완독은 명시적 행위다. `record_progress()`는 자동 완독 판정을 하지 않는다.
- **`percent` 단위는 `target_value = 100` 고정**, `page` 단위는 `target_value` 필수. 스키마 제약으로 강제된다.
- **완독·중단된 회차에는 진행을 기록할 수 없다.** RPC가 거부한다.
- 검증 한계값(소감 500자, 별점 0.5 배수, 인용 위치)은 **`src/lib/`와 DB 제약 양쪽에 같은 값으로** 있다. 한쪽만 고치면 사용자가 한국어 메시지 대신 Postgres 오류를 본다.
- **태그는 대소문자를 무시하고 같은 것으로 본다.** DB의 `unique(user_id, name)`은 대소문자를 구분해서 `SF`와 `sf`가 둘 다 들어갈 수 있다. 그걸 막는 건 앱의 몫이고, 판정 기준은 `lib/taxonomy/tags.ts`의 `tagKey()` 하나뿐이다. 입력·자동완성·병합이 전부 이걸 쓴다.
- **분야·태그·서재를 지워도 책은 지워지지 않는다.** 분야는 `on delete set null`, 태그·서재는 조인 행만 cascade로 사라진다. 삭제 확인 문구가 이걸 명시하므로 동작을 바꾸면 문구도 같이 고친다.
- **서비스워커는 `/api/`·`/auth/`·다른 도메인을 캐시하지 않는다.** 여기가 뚫리면 남의 세션으로 받은 응답이 브라우저에 남는다. 방문 화면 캐시(pages)는 로그아웃할 때 지운다 — 기기를 나눠 쓸 때 이전 사람의 서재가 오프라인으로 보이면 안 된다.
- **앱 이름은 "독서대", 저장소·내부 식별자는 `book-reader`다.** 화면·브라우저 탭·매니페스트는 독서대를 쓰고, `package.json`의 name·백업 파일명(`book-reader-2026-08-01.json`)·서비스워커 캐시 키는 그대로 뒀다. 이미 내려받은 백업 파일, 이미 만들어진 캐시와 어긋나지 않게 하기 위해서다. 둘이 달라 보여도 실수가 아니다.
- **PWA 자산(`/manifest.webmanifest`, `/icons/*`, `/sw.js`)은 공개 경로여야 한다.** 브라우저가 로그인 상태와 무관하게 가져가므로, 보호 라우트로 두면 로그인 HTML이 돌아와 서비스워커 등록이 통째로 실패한다. W13에서 실제로 걸렸고 E2E가 잡았다.
- **백업은 관계를 id가 아니라 이름으로 저장한다.** 분야·태그·서재는 사용자 안에서 이름이 유일하므로 자연키가 된다. 그래서 파일이 사람이 읽을 수 있고, **다른 계정으로 옮겨도 복원된다**(E2E가 이걸 검증한다). UUID로 이었으면 옮길 수 없다.
- **가져오기는 덮어쓰지 않고 얹는다.** 실수로 올린 파일 하나에 서재가 사라지면 안 된다. 이미 있는 책은 ISBN(없으면 제목)으로 걸러 건너뛴다. 트랜잭션이 아니라 책 단위로 넣으므로, 중간에 끊겨도 재시도가 안전하다.
- **통계는 SQL view가 아니라 앱에서 집계한다.** CLAUDE.md가 "통계 집계는 `src/lib/`에 분리해 단위 테스트 대상으로"라고 못박고 있고 W10의 DoD도 V2(집계 결과 검증)다. 마이그레이션이 없으므로 게이트도 없다.
- **차트 라이브러리를 쓰지 않는다.** 도넛과 막대 둘뿐이라 SVG로 직접 그린다. 서버 컴포넌트에서 렌더되어 클라이언트 JS가 0이고, 각도 계산은 `lib/stats/chart.ts`가 순수 함수로 갖고 있어 단위 테스트가 덮는다.
- **날짜는 전부 서울 기준이다.** `getFullYear()`를 쓰면 12월 31일 밤 완독이 서버와 브라우저에서 다른 해로 잡힌다. `lib/stats/aggregate.ts`의 `seoulDate`·`seoulToday`를 쓴다.
- **서재는 전량 로드 후 클라이언트에서 거른다** (PRD §5). 페이지네이션·무한 스크롤이 없다. 필터·정렬 로직은 전부 `lib/library/filter.ts`의 순수 함수이고 단위 테스트가 조합을 덮는다. 1,000권을 넘어가면 그때 서버 필터링으로 옮긴다.
- **조인 테이블(`book_tags`·`shelf_books`)은 `user_id` 컬럼이 없다.** 부모 소유권을 `exists`로 따라가고, `with check`가 **부모 양쪽**을 본다 — "남의 책에 내 태그"와 "내 책에 남의 태그"를 둘 다 막아야 한다. V3가 네 방향 모두 검증한다.

### 5.4 테스트

- **E2E는 개발 서버가 아니라 프로덕션 빌드를 대상으로 돈다.** 개발 서버는 라우트를 요청 시점에 컴파일해서, 테스트가 쌓이면 엉뚱한 곳에서 타임아웃이 났다. 되돌리지 말 것.
- **Playwright는 `workers: 1`, 파일당 로그인 1회, 페이지 공유.** 테스트마다 로그인하면 Supabase 인증 요청이 20번 넘게 몰려 간헐적으로 TLS 오류·워커 크래시가 났다. 병렬로 되돌리면 재발한다.
- `test.use({ storageState })` + `beforeAll` 조합은 **쓰지 않는다.** 첫 테스트의 컨텍스트가 `beforeAll`보다 먼저 만들어져 파일이 없다고 실패한다.
- **UI를 바꾸면 기존 E2E가 깨질 수 있다.** W7이 완독을 모달로 바꾸면서 W5 테스트 2개가 실제로 깨졌다. 전체 스위트를 돌려 확인한다.
- **테스트를 통과시키려고 단정을 약화시키지 않는다.** 실패하면 실패 출력을 붙여 보고한다.
- **`getByText`는 입력칸 값에도 걸린다.** 방금 타이핑한 textarea가 잡혀서, 저장이 끝나기 전에 단정이 통과하고 다음 `goto`가 insert를 앞지른다. 저장 결과를 확인할 때는 목록에 렌더된 요소(`locator("p", { hasText })` 등)로 집는다. W10에서 이걸 앱 캐시 버그로 오진해 한참 헤맸다.

### 5.5 환경·도구

- **corepack이 pnpm을 못 받으면 `packageManager` 필드를 확인한다.** `package.json`에 이 필드가 없으면 corepack이 매번 "최신 pnpm"을 조회하는데, 그 서명 검증이 깨져 `Cannot find matching keyid`로 죽는다. 필드로 버전을 고정해두면 재발하지 않는다. 임시로 뚫어야 하면 `COREPACK_INTEGRITY_KEYS=0`.
- **`src/proxy.ts`가 미들웨어다.** Next.js 16에서 `middleware.ts` → `proxy.ts`로 바뀌었고 export 이름도 `proxy`다. 문서에서 "middleware"라고 부르는 것은 이 파일이다.
- **PowerShell은 heredoc(`<<'EOF'`)을 지원하지 않는다.** 여러 줄 커밋 메시지는 Bash 도구를 쓰거나 PowerShell here-string(`@'…'@`, 닫는 `'@`는 반드시 0열)을 쓴다.
- **Git 계정이 저장소별로 분리돼 있다.** 전역 설정은 github.com의 credential helper를 `gh` CLI(활성 계정 `kyhoon-hj`)로 지정하는데, 이 저장소는 로컬 config에서 helper 체인을 초기화하고 GCM으로 교체해 `victoriatech25`를 쓴다. `.git/config`의 `[credential "https://github.com"]` 블록을 지우면 푸시가 다른 계정으로 시도되어 거부된다.
- `.gitattributes`가 `eol=lf`로 고정한다. Prettier가 LF로 쓰고 Windows 체크아웃이 CRLF로 되돌리며 파일이 영구히 "수정됨"으로 보이던 문제를 막는다.

## 7. 디자인 시스템 (W7.5)

컨셉은 **"서재"** — 제목·인용구·소감은 세리프로 책처럼, 본문·폼은 산세리프로 앱처럼. 순백/순검정 대신 따뜻한 종이톤(`#FAF9F7`)과 먹색(`#2A2724`)을 쓴다.

**규칙 하나만 지키면 된다: 화면 코드에 팔레트 이름을 쓰지 않는다.**

```
❌ bg-zinc-50  text-zinc-900  dark:bg-zinc-950
✅ bg-background  text-foreground  bg-card  text-muted-foreground  border-border
```

`dark:` 유틸리티도 쓰지 않는다. 토큰이 라이트/다크 값을 이미 가지고 있어서 한 번 쓰면 양쪽이 같이 따라온다. W7.5 이전에는 `zinc-*` 317건과 `dark:` 184건이 흩어져 있었고, 그래서 컨셉을 바꾸려면 전 화면을 뒤져야 했다.

| 파일                          | 역할                                                            |
| ----------------------------- | --------------------------------------------------------------- |
| `src/app/globals.css`         | **토큰 정본.** 색·타이포 눈금·라운드. 컨셉 변경은 여기서 끝난다 |
| `src/components/ui/styles.ts` | 공용 클래스 문자열(`input` `buttonPrimary` `card` …)            |
| `src/app/layout.tsx`          | 테마 클래스 주입 스크립트 + 숫자용 웹폰트                       |

**주의점**

- **컨트롤은 앱 규칙을 따른다 (W14.5).** 누를 자리는 `min-h-11`(44px), 누르면 `active:scale-[0.97]`, 입력칸은 테두리 대신 면(`bg-secondary`)으로 채우고 포커스에서만 테두리를 세운다. 밑줄 링크는 쓰지 않는다 — 보조 동작도 눌리는 알약이다. 규칙 전문은 `styles.ts` 머리 주석에 있다.
- **좁은 화면에서 입력 글자는 16px로 올린다.** 본문 눈금(`--text-sm`)이 15px인데, iOS Safari는 16px 미만 입력칸에 포커스가 가면 화면을 확대한다. `globals.css`의 `@media (max-width: 640px)` 규칙이 그것만 막는다.
- **`--elevated`는 "트랙 위로 떠오른 면"이다.** 세그먼티드 컨트롤의 고른 칸에 쓴다. `--card`를 쓰면 안 된다 — 다크에서는 card가 secondary보다 **어두워서** 고른 칸이 오히려 가라앉는다.
- **`styles.ts`의 `input`에는 폭이 없다.** 호출부가 `w-full` 또는 `w-24`를 붙인다. 여기에 `w-full`을 박으면 좁게 쓰려는 곳에서 덮어쓰기 싸움이 나고, 실제로 한 번 났다.
- **한글 웹폰트는 없다.** `next/font/google`은 한글 서브셋을 제공하지 않는다(구글이 동적 서브셋으로 서빙한다). `subsets: ["latin"]`으로 받으면 라틴만 웹폰트가 되고 한글은 폴백으로 갈라져 더 나빠진다. 그래서 시스템 폰트 스택을 쓴다. Pretendard·고운바탕을 셀프호스팅하려면 패키지 추가나 폰트 파일 반입이 필요하다 — **새 의존성이므로 컨펌 사항**이다.
- **테마는 넷 중 하나다: 시스템(기본) · 라이트 · 다크 · 세피아.** 시스템일 때는 **클래스를 붙이지 않는다** — `globals.css`의 `prefers-color-scheme` 규칙이 그대로 먹어서 OS 설정 변경을 CSS가 직접 따라간다. JS 리스너가 없고 JS가 꺼져도 동작한다. 직접 고른 경우에만 클래스가 붙어 그 규칙을 덮는다.
- **세피아는 OS에 짝이 없다.** 밝기 0.9 언저리의 미색 종이톤이라 `prefers-color-scheme`으로는 도달할 수 없고, 사용자가 직접 골라야만 켜진다. `resolveTheme`이 시스템일 때 세피아를 내놓지 않는 이유다. `prefers-color-scheme: dark` 규칙의 선택자에서도 `:not(.theme-sepia)`로 빼야 한다 — 안 그러면 OS가 다크일 때 세피아가 덮인다.
- **세피아의 html 클래스는 `sepia`가 아니라 `theme-sepia`다.** Tailwind에 `.sepia`(= `filter: sepia(100%)`) 유틸리티가 있어서, 같은 이름을 html에 붙이면 화면 전체에 필터가 걸린다. 빌드된 CSS에 실제로 그 규칙이 들어 있는 것을 확인하고 피했다. 단위·E2E 양쪽에 이 단정을 남겨뒀다.
- **선택은 `localStorage.theme`에 저장한다. 시스템은 키를 지우는 것으로 표현한다.** `"system"`이라는 값을 넣어두면 첫 페인트 스크립트가 그걸 클래스 이름으로 쓸 위험이 있다.
- **테마를 바꾸면 150ms 동안 색이 보간된다.** `transition-colors`가 붙은 요소들이 한꺼번에 넘어간다. 스크린샷을 찍을 때 이 중간을 잡으면 두 테마가 섞여 보인다 — W11에서 이걸 색 버그로 오해했다.
- **차트 색(`--chart-1~5`)은 이미 유채색으로 잡아뒀다.** W10에서 도넛·바를 그릴 때 무채색이면 구분이 안 된다.
